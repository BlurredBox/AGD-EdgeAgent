# Security and reliability audit, 2026-11-04

Read-only audit of `main` at 21643f7. 28 findings: 3 must fix, 13 fix soon, 12 minor. Each is also a GitHub issue labelled `audit-2026-11-04`.

This repo is an older, partial snapshot of the edge agent. Some findings are already fixed in the internal development tree and only need to reach this repo; each such finding says so. Tests here pass: 56 passed, and the contracts runner shows 12 passed and 2 skipped.

Not covered: connector modules and installers not in this repo, server behaviour, Windows at runtime, statistical correctness of the detectors.

### F3. Stop or restart inside a window emits an early-closed partial window; duplicate window id overwrites or is refused
- Label: must-fix-before-pilot (fixed in the internal development tree, not here). Severity: high.
- Location: edge_agent/windows.py:58-59 (`flush` closes every open bucket including the current one), edge_agent/agent.py:226-241 (SIGTERM -> `close()` -> `flush()`), edge_agent/transport.py:50 (spool name = window end in ms), edge_agent/wire.py:123-126 (window_id = hash of model and window end), windows.py:34 (`_closed_upto` kept only in memory).
- Scenario: any `systemctl restart`, deploy or host reboot mid-window flushes the open window early with its real end timestamp. After restart the rest of that window's rows form a second window with the same end, the same window_id and the same spool filename. Repro: first stop wrote `001700000100000.json`; after the second stop the directory still held one file (the second partial overwrote the first). If the first was already sent, the second is a replay on the server (data silently discarded) or refused. A window closed early is refused by the server, and a refusal 4xx goes to rejected/ (F4).
- Status: CONFIRMED (run). Fixed in the internal tree; the fix has not reached this repo.
- Sensitive: no.

### F4. 401, 403, 404, 422 and every other non-retryable 4xx permanently retire the window
- Label: fix-soon (this repo has no replay tool). Severity: high.
- Location: edge_agent/transport.py:36, 150-158, 172-177 (`_deterministic`), 78-79 (`reject`).
- Scenario: a missing or rotated API key (SDK answers 401), a clock that drifts past the server's tolerance (SDK stamps `time.time()` per attempt; skew gives 401 on every window), a reverse proxy returning 404 during a deploy, or a server-side validation tightening (422) moves every queued window to `rejected/` one by one, no retry. Repro: statuses 401, 403, 404, 422 each gave queued 0, rejected 1; 301 and 500 stayed queued. In public the moved file has no record of why (no receipt), and nothing resends it. 33 days of queue can be emptied in one drain.
- Status: CONFIRMED (run, status table). 
- Suggested: treat 401/403/404/405 and 5xx-like proxy statuses as retryable-with-alert (queue held), keep 422/400 as final; alert loudly on the first 401.
- Sensitive: no.

### F5. Crash, kill or power loss loses tailed rows (offset is saved before the rows are in any durable window)
- Label: fix-soon. Severity: medium-high.
- Location: edge_agent/adapters.py:109 (`_save_offset` at the end of `poll`, before the agent ingests), agent.py:159-183, windows.py (open windows only in memory), signals.py:101-107 (state saved after each window).
- Scenario: SIGKILL, OOM kill or power loss after a poll: the offset is already past the rows, the open window is in memory only, so up to one cadence (plus up to 10,000 polled rows) is gone and never emitted. Repro: 40 rows tailed, `del agent` (no flush), new agent re-read 0 rows. Also `offset_file` write has no fsync and no flush of the directory.
- Status: CONFIRMED (run). The internal tree's stop fix covers a clean stop only.
- Sensitive: no.

### F6. One future-timestamped row closes the current window early and strands a future bucket
- Label: fix-soon. Severity: medium.
- Location: edge_agent/windows.py:44-51 (`add` closes every earlier bucket when a record arrives for a later bucket), 53-56, 58-59.
- Scenario: a single record dated a year ahead (bad clock on the model host, a naive local-time stamp in a UTC- zone, a test row) closed the current window with 10 rows, set `_closed_upto` so the rest of that window's rows were dropped as late (`late_dropped` 1), and left the future bucket open; at the next shutdown `flush` emitted a window ending a year in the future (server refuses early/future windows, F4). For naive local timestamps in a UTC- zone the whole feed is "ahead" and windows are held by the wall clock for hours. Trajectory-slot index poisoning from the far-future window is plausible (slot_state is keyed by absolute bucket index and persisted) and not tested.
- Status: CONFIRMED (run, cutter-level); trajectory effect PLAUSIBLE. 
- Sensitive: no.

### F7. Corrupt or incompatible per-model state: crash or silent cold start, no fsync
- Label: fix-soon. Severity: medium.
- Location: edge_agent/signals.py:91-107 (`_load` catches only OSError, UnpicklingError, EOFError; `save` has no fsync before `os.replace`).
- Scenario: a state file that unpickles to a non-dict (None) crashed agent construction with `TypeError: argument of type 'NoneType' is not iterable` (run), which is a crash loop under systemd. A truncated or empty file (power loss after replace without fsync) is silently treated as a first start: the 200-window reference (about 16.7 h at 5 min) is rebuilt from scratch with no alert and the trajectory state resets. After an upgrade that changes a pickled class (ReferenceWindow, trajectory `_SlotState`), unpickling can raise AttributeError or ModuleNotFoundError, which is not caught (PLAUSIBLE). Unpickling also executes code if anyone but the agent user can replace the file (state dir is created 0755, F11).
- Status: TypeError and silent cold start CONFIRMED; upgrade crash PLAUSIBLE.
- Sensitive: no.

### F8. Head-of-line blocking: one retryable failure stops the whole drain, across all models
- Label: fix-soon. Severity: medium.
- Location: edge_agent/transport.py:130-161 (`return sent` at line 161 leaves the loop over every model's files).
- Scenario: one window that always gets a 5xx or a 3xx (an http-to-https redirect, a gateway returning 502 for one payload) blocks that model's later windows and every other model's, indefinitely; backoff is 5..300 s, the queue grows until the 33-day age cap silently deletes the oldest. 301 stayed queued in the repro.
- Status: CONFIRMED by reading plus the 301/500 run. Sensitive: no.

### F9. A spool file that is valid JSON but incomplete crashes the agent in a loop

- Status: CONFIRMED (run). Sensitive: no.

### F10. Any non-ValueError from ingest or window computation after the offset moved loses data
- Label: fix-soon. Severity: medium.
- Location: agent.py:171-176 (only `ValueError` caught), 268-278 (a failing window is dropped, not spooled), 313-319 (`OSError` on spool write re-raised, run exits), `__main__.py:98-101`.

The alert says "local source replay required" but this repo ships no replay tool; un-doing it means deleting `source.offset`, which re-reads the entire file and re-emits already-sent windows.

### F11. Default permissions are permissive and the secret is easy to leak
- Label: minor. Severity: low-medium.
- Location: edge_agent/agent.py:74 and transport.py:43 (`mkdir` default mode), tripwires.py:70 (alerts.jsonl opened with default mode), config.py:18 (`secret` in a dataclass, `repr` shows it), `__main__.py:80-82`.
- Scenario: on a multi-user host the state dir and spool dir are 0755 and `alerts.jsonl` is 0644 and contains customer feature names (alerts "may name feature names", tripwires.py:5). Run: state 0o755, alerts.jsonl 0o644, spool 0o755 (files inside are 0600). Any traceback or log line that prints the config object includes the HMAC secret (`'TOPSECRETVALUE' in repr(cfg)` is True). The secret may sit in plaintext in agent.json; no mode check. `secret_env` naming a missing variable is a bare `KeyError`. Kit installs set UMask=0077 through their systemd unit; manual runs from this repo do not.
- Status: CONFIRMED (run). Sensitive: no.

### F13. Rotation to a larger file silently skips rows and mis-parses mid-line
- Label: fix-soon. Severity: medium.

### F14. Late rows are dropped with default `lateness_seconds=0`
- Label: fix-soon. Severity: medium-low.
- Location: config.py:30, windows.py:47-49, agent.py:193.
- Scenario: windows close the moment the wall clock passes the boundary; any row whose log write or flush trails by even a second is dropped as late (repro: a row stamped 1 s before the boundary arriving 2 s late was dropped). Raises `ingest_dropped_fraction` and `ingest_incomplete_flag` on healthy feeds and can trip `ingest_degraded` withholding of statistics when volume is low.
- Status: CONFIRMED (run). Sensitive: no.

### F15. Outcome join commits and syncs per prediction row
- Label: fix-soon. Severity: medium-low.
- Location: edge_agent/outcomes.py:65-80 (`with self.db:` per `register`, plus an unconditional DELETE), 142-147 (`expire` commits every tick).
- Scenario: with `prediction_id` present on every row the agent is capped by sqlite commit latency. Measured on a loaded host under `ionice -c3`: 1000 registers in 16.7 s = 60 rows/s. Above that, `poll` of 10,000 rows takes minutes, blocking `tick` (window closing, sending, status) in the same thread.
- Status: CONFIRMED on a loaded host; other hardware not measured. Sensitive: no.

### F16. Price fetch blocks the main loop and has no response or redirect limits; it also discloses instrument ids to a third party
- Label: fix-soon. Severity: medium-low.
- Location: edge_agent/prices.py:67-71 (`httpx.get(..., follow_redirects=True)`, 15 s timeout, no size cap), 119-135, agent.py:190-191 (`prices.refresh` inline in `tick`), prices.py:65 (`series` id placed unescaped into the URL and into a filename, 103).
- Scenario: (a) in a network that drops outbound traffic every configured series costs up to 15 s per refresh inside `tick`, delaying window closing and sending (first tick included). Off by default (`instrument_series` empty). (c) A hostile config value `../x` would write outside `prices/` (operator-controlled config, low).
- Status: (a),(b) CONFIRMED by reading; not exercised live. Sensitive: no.

## Checked and clean

- Secrets: no keys, tokens, passwords, certificates or .env in tree or in history (single commit, no tags, no other branches; ). The only secret-looking literal is the test fixture `s3cret-s3cret-s3cret` (tests/edge_agent/synth.py:28), obviously fake. No IPs, internal hostnames, domains, customer names, absolute home paths.
- TLS: no `verify=False` anywhere; SDK `httpx.Client` defaults verify on; `ca_file` uses `ssl.create_default_context(cafile=...)` and `client_cert` loads a chain; the SDK client does not follow redirects (a 3xx is a failure, so credentials do not follow a redirect). mTLS options are validated as two non-empty path strings (config.py:61-67).
- HMAC: SDK signs `timestamp:nonce:canonical_body`, fresh nonce and timestamp per attempt, `hmac` + SHA-256, canonical JSON via orjson sorted keys; window_id is deterministic per (model, window end) so replays dedupe. Secret is not logged by the public code; error text is cut to 200-300 chars; no logging of the Authorization header.
- Wire boundary: `wire.audit_z_t` allow-lists names, types and sizes (<=500 fields, ascii text <=128, feature-keyed maps must start `f_`); feature names are replaced by HMAC-salted ids; `tests/edge_agent/test_wire_audit.py` checks sentinels never appear. feature_ids.json is 0600 and written via temp file + rename.
- SQL: the only database is the local sqlite outcome join; all statements are parameterised. No subprocess, `eval`, `exec`, `os.system`, `shell=True` or YAML load in the public tree.
- Sources: this repo has only a JSONL tail, an outcome tail and an in-process adapter; no network source, no Postgres, Kafka or folder code to attack.
- Dependencies: `pip-audit -r requirements-edge.txt --no-deps`: no known vulnerabilities.
- Tests: 56 passed in 55 s (network-isolated) with the SDK on PYTHONPATH. `contracts/signal_vector/runner.py`: 12 passed, 2 skipped (sketch fixtures are stubs, runner.py:278 TODO).
- Spool durability for the normal path: temp file, flush, fsync, `os.replace`, 0600 files; a window is spooled before sending; `drain` removes only after an accepted send; order is oldest first within a model.
- Status file: written atomically at 0600 and contains counts only.
- Kit installs use a hardened systemd unit (NoNewPrivileges, ProtectSystem=strict, PrivateTmp, empty capability set, UMask=0077). It is missing from this repo (F1).
